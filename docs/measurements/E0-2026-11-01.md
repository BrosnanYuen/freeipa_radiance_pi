| Cold prefill throughput | **1,361.8 tok/s** |
| Warm TTFT (196,608 cached prompt tokens) | 1.746 s |
| Decode throughput at ~198k context | **23.8 tok/s** (128-token sample); 23.7 (32-token sample) |
| Peak VRAM (sysfs `mem_info_vram_used`) | **20.58 GiB** |
| Full-length sessions (`M`) | **1.0** |
| `ctx_max` | **200,000** (prompt admitted at 197,952; limit 200,000) |

The decode sample is short by design; a longer generation at 200k would refine
the tok/s, but the admission and prefill numbers are the E0 gate. The cold run
was the first request after load; the warm run reused 196,608 prefix-cache
tokens, which confirms the prefix cache is active at this context.

## Reproduce

```sh
# one-off placement receipt (mock stopped, edge running)
docker run ... radiance --model /models/qwen3.8-27b-mxfp4.rad ... --debug-placement
# tokenize and measure (payload on stdin; key read inside the edge)
docker compose exec -T radiance-gateway bash -c '
  printf "header = \"Authorization: Bearer %s\"\n" "$(cat /secrets-src/radiance_api_key)" > /tmp/radiance.hdr
  curl -sS -K /tmp/radiance.hdr -H "Content-Type: application/json" \
    --data-binary @- http://127.0.0.1:8000/v1/chat/completions' < payload.json
```

The full startup log is `run/e0/debug-placement.log` (gitignored). The
`--debug-placement` invocation still served normally; the timeout used for the
one-off run is the only reason it was stopped.
